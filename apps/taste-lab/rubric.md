# Taste Lab 评审准则（精简版，来源：design-taste + Impeccable）

## 评分公式
- 网站：总分 = 0.45 × metric_score（脚本已给） + 0.55 × visual_score（你给 1–10）× 10
- 图片：总分 = 0.6 × metric_score + 0.4 × visual_score × 10（无 metric 则只看视觉分）

## 视觉分档（网站）
9 标杆级（一个焦点、签名字体、节奏完美）｜8 克制且有记忆点，略有瑕疵｜7 干净合格但偏通用｜5–6 模板感、模块拥挤、层级弱｜3–4 门户墙，无焦点｜≤2 未设计或损坏

## 视觉打分维度（每项都要具体到可见证据）
1. 留白与间距节奏：区块间距是否成体系（建议 8/16/24/48/64/96），有无塌陷或拥挤
2. 层级清晰度：首屏是否只有一个主焦点，标题/正文/辅助信息三档是否分明
3. 一致性：颜色数、字号档数、圆角、阴影、字体家族是否收敛
4. 签名元素：有没有一个让人记住的东西（独特字体、色彩处理、图形语言、版式创新）
5. AI 模板感：泛用渐变、圆角图标块上标题、卡片套卡片、无意义装饰、居中一切
6. 排版：正文行长 45–75 字符、行高 1.5–1.7、标题用 clamp、字重层级
   6b. 中文字体：中文网页正文与标题一律用黑体族（思源黑体 / 苹方 / 微软雅黑 / HarmonyOS Sans）。
   宋体、仿宋、楷体、中文衬线体在现代网页里已过时（印刷品遗留），出现即为 P1 问题；
   tokens.font_family 不要给宋体或衬线体。
7. 色彩：主色 1 个 + 强调色 1 个，正文对比度达 WCAG AA 4.5:1
8. 移动端：无横向溢出、点击区 ≥44px、首屏仍是一句话主张
9. 文案：有无陈词滥调（赋能、引领、生态、颠覆）、占位文案

## 指标阈值（脚本 metrics.json 的判读）
- **先看 pageType**：阈值已按页面类型分化，不要拿落地页的尺子量后台页。
  | 类型 | 颜色 ≤ | 主标题 ≥ | 正文 ≥ | 字号档 ≤ |
  |---|---|---|---|---|
  | landing 落地页 | 12 | 48px | 16px | 7 |
  | app 应用/后台 | 14 | 22px | 13px | 8 |
  | doc 内容/文档 | 12 | 28px | 15px | 8 |
  | commerce 电商 | 14 | 30px | 14px | 8 |
  | login 登录页 | 10 | 22px | 14px | 6 |
- **颜色数已按 CIELAB ΔE 聚类**：`colorsTotal` 是色簇数，`colorsRawTotal` 是原始色值数。
  只有两色彩值肉眼几乎无差时才被合并——谈"颜色泛滥"一律以聚类后数字为准。
- colorsTotal 超预算每个 -4.5、gradients 超 3 每个 -1.5
- fontSizesSig 超预算每个 -10、fontCount >2 每个 -12、fontWeights >3 每个 -8
- 正文小于类型下限：字号分每个 -5 px，层级分每个 -3 px
- 层级：按 hero/正文 比例与该类型理想值（落地页 3.5｜应用 2.0｜文档 2.4｜电商 2.6）的偏差打分，
  不再是"比例越大越好"
- 无障碍：**真实 WCAG**。正文对比度 P50 ≥4.5:1 达标（AA），≥7:1 为 AAA；
  低于 AA 的文本占比每 1% 扣 0.6 分。v1 用 12:1 当达标线是错的，已废弃。
- `dimensions.<维度>.measured = false` 表示该维度**没采到数据**（例如整页没有正文段落）。
  这种维度不许编分数、不许编问题；报告里明说"未测"即可。

## 图片额外维度
主体清晰度、构图（黄金分割/三分法）、色彩和谐与饱和、对比与光影、分辨率与显示尺寸匹配、
AI 伪影检查（多余手指、扭曲文字、不对称瞳孔、涂抹感、重复纹理、异常边缘）、风格与用途匹配。

## 问题分级
P0 破坏性/阻断（对比度不可读、布局崩坏、移动端溢出、主行动不明确、无焦点状态）
P1 质量与一致性（无设计方向、token 债务、层级弱、卡片套卡片、装饰性渐变、无 reduced-motion）
P2 打磨（陈词滥调文案、光学对齐、图标尺寸、标题 text-wrap: balance、hover 微交互）

## 输出要求
- 有分区图时：P0/P1/P2 各最多 3 条、总数 ≤ 9；无分区图时各最多 2 条、总数 ≤ 6。
  宁缺毋滥——某个区域真没毛病就不要为它编问题。
- 每条 issue 带 `region`（侧栏 / 顶栏 / 主栏 / 表单 / 全局）
- 每条 problem 指向具体可见问题（"首屏 CTA 按钮与背景对比仅 2.1:1"），fix 给可落地参数（"改 #6E9BFF 底 + #0D0E10 字，对比 ≥4.5:1"）
- `anchor`：从截图上原样抄一句可见文案（2–20 字），用于把这条问题在截图上框出来。
  找不到对应文案就输出空字符串，**不要编**。
- tokens 给出可直接抄进 CSS 的值：font_family / font_size_hero / body_size / primary_color / accent_color / radius
- 中文输出，克制，不要套话
- 「fix」字段写成能直接交给 AI 编程工具（Claude Code / Cursor / OpenClaw）执行的中文指令：必须带具体数值（px / 色值 / 比例）与改法，不要写「优化一下」「再调调」这类空话
- tokens.font_family 必须是黑体族，不得出现宋体 / 仿宋 / 楷体 / 衬线体
- 若是登录页场景（metrics.loginWall=true）：不要把登录表单当设计缺陷，在 summary 里说明「本次只采集到登录页」，并把重点放在「需要登录态才能评审真实界面」这一提示上
